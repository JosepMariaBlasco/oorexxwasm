Rexx in a web page

Each example below is one small HTML file. Its program is a <script type="text/rexx"> element, run in your browser by the real ooRexx interpreter, compiled to WebAssembly. The server does nothing but send the file: any web server will do, as long as it sends two headers (see Serving pages like these).

Reverse

Today's date, a field and a button: clicking the button reverses the text. A Rexx object handles the click.

Serving pages like these

  
The page loads ooRexx.js from a directory that holds the
  runtime, and the server must send Cross-Origin-Opener-Policy:
  same-origin and Cross-Origin-Embedder-Policy: require-corp
  (the interpreter's threads need them). With ?rexx-debug=1 in the
  address, the page opens Dom Wise's ooRexx debugger: set breakpoints, step,
  and watch the variables, also inside the event handlers. The runtime, an
  .htaccess for Apache and a small server for Node are in the
  browser distribution: see
  INSTALL.md.
